# Terraform EKS Plan Triage Notes

## False Leads Ruled Out

- A saved plan is not safe because it is not applied yet; approval still authorizes the blast radius.
- Managed node group replacement is still blast radius when capacity, subnets, and workloads move at the same time.
- One-subnet coverage is not a temporary detail when it removes multi-AZ scheduling during replacement.
- Public ingress for `443` is not safe just because the port is HTTPS.
- eks:* is not reviewable least privilege, even for a platform automation role.
- Rollback after apply is not obvious when replacement, capacity, ingress, and IAM changes are bundled.

## Strong Evidence

- `tfplan.txt` shows `module.eks.aws_eks_node_group.apps must be replaced`.
- `subnet_ids` regresses from two subnets to only `subnet-bbb222`.
- Desired capacity changes from `6` to `3`, and max capacity changes from `12` to `6`.
- The plan opens `443` to `0.0.0.0/0` and grants `eks:*` on `*`.

## Decision Trap

Do not approve the plan because it is generated by Terraform or because it is "only" infrastructure. The safe decision is to block, split the changes, require rollback notes, and scope network and IAM changes before apply.
